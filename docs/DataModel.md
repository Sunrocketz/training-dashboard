# Модель данных

## Лист-источник

- Имя: `Контроль штата обучения` (`SOURCE_SHEET_NAME`)
- Диапазон чтения: строки `DATA_START_ROW`…`DATA_END_ROW` (1–500), все колонки до последней заполненной (`getLastColumn()`); поля ищутся по заголовкам
- Часовой пояс скрипта: `Asia/Oral` (`appsscript.json`)

## Журнал ОС (вторая книга)

Не в той же таблице. Конфиг: `LINE_REVIEW_SPREADSHEET_ID`, лист `2026`.

| Index | Колонка | Ключ | В API |
|------:|---------|------|-------|
| 0 | A | сотрудник | **нет** (ПДн) |
| 2 | C | тренер | только для склейки |
| 3 | D | скрипт | да/нет → rate (E — комментарий, не читаем) |
| 5 | F | возражения | да/нет → rate (G — комментарий) |
| 7 | H | CRM | да/нет → rate (I — комментарий) |
| 12 | M | подготовка 1–5 | среднее; текст без числа отбрасывается |

Не читаем: прогноз (L), слабые/сильные стороны (J/K), «чего не хватило» (N), первый день (O), ФИО. Шапка (строки 1–2) и «Дата старта/выхода группы» пропускаются.

`parseScore15`: `4`, `4,7`, `4.5`, `4.,5` → число 1–5 с одним знаком. Диапазон `3,5–4` и «50/50» — не оценка. Источник балла — только колонка M.

Склейка тренера: `trainerMatchKey` = фамилия + имя после среза префикса «Тренер»; в ключе `ё`=`е` (список ОС без «ё»). Имя на экране — как в «Контроль штата». Несовпадения → `totals.lineReview.unmatched`. Уволенные (`DEPARTED_TRAINERS`) остаются в агрегатах; UI добавляет метку «(Уволен)».

Ошибка доступа ко второй книге **не** валит весь дашборд: `metrics.lineReview.ok: false`, обучение считается как раньше.

## Колонки листа (поиск по заголовкам, ADR-022)

С 18.11.2026 скрипт **не привязан к буквам колонок**. `readSourceRows()` находит строки заголовков (в колонке A — «Месяц, группа»; они повторяются над каждым блоком месяца), по тексту заголовков (`HEADER_PATTERNS`) определяет, где какое поле, и раскладывает строку во внутренний порядок `COL`. Перестановка, вставка или удаление колонок дашборд не ломает, пока **названия** заголовков узнаваемы. Если обязательная колонка не нашлась — `/exec` отвечает понятной ошибкой, а не неверными цифрами.

Раскладка листа на 18.11.2026 (A–V) и как заголовок узнаётся (регистр, `ё`, переносы строк и хвосты вроде «(ПЛАН 37%)» не важны):

| Колонка | Заголовок в листе | Поле | Узнаётся по | Обязательна |
|---------|-------------------|------|-------------|:-----------:|
| A | Месяц, группа | `monthGroup` | начинается с «месяц, группа»; месяц = часть до `,` | да |
| B | Тренер группы обучения | `trainer` | «тренер группы» | да |
| C | Дата старта группы | `startDate` | «дата старта»; **Date обязательна**, иначе строка пропускается | да |
| D | Дать выхода на линию | `lineDate` | «дата/дать выхода»; группа законченная, если D ≤ сегодня | да |
| E | Сколько вышло на 1-ый день… | `day1` | «вышло на 1-ый день» | да |
| F | Сколько людей УШЛИ САМИ | `leftSelf` | «ушли сами» | да |
| G | % ушли сами… | `leftSelfPct` | начинается с «% ушли сами» | нет |
| H | Скольким людям ОТКАЗАЛИ МЫ | `refused` | «отказали мы» | да |
| I | % отказа компании… | `refusedPct` | «% отказа» | нет |
| J | сколько перенесли в другую группу | `transferred` | «перенесли» | да |
| K | % переноса | `transferredPct` | «% переноса» | нет |
| L | Кол-во на начало 2-го дня | `day2Start` | «начало 2-го дня» | да |
| M | % Конверсии с 2-го дня | `conv2` | «конверсии с 2-го дня» | нет |
| N | Кол-во на начало 3-го дня | `day3Start` | «начало 3-го дня» | да |
| O | % Конверсии с 3-го дня | `conv3` | «конверсии с 3-го дня» | нет |
| P | Кол-во на начало 4-го дня | `day4Start` | «начало 4-го дня» | нет (новая, с ноября 2026) |
| Q | % Конверсии с 4-го дня | `conv4` | «конверсии с 4-го дня» | нет (новая) |
| R | Количество людей на выход | `exitCount` | начинается с «количество людей на выход» | нет (новая) |
| S | % на выход от 1-го дня | `exitPct` | начинается с «% на выход» | нет (новая) |
| T | Сколько людей на выход группы на линию | `finalCount` | «выход группы на линию» — **итог** (в листе формула E−F−H−J) | да |
| U | % с 1-го по 5-ый день, вышли на линию | `conv1to5` | начинается с «% с 1-го по 5» | нет |
| V | Комментарий | `comment` | «комментари…» — тип группы («1-ый уровень», «Force Group», «Сервисная»…) или статус («не собралась / не набралась / не состоялась», «распалась / расформирована»). Не писать ФИО и личные данные | да |

**Пусто ≠ 0.** Новые колонки P–S у групп до ноября 2026 пустые → в API `null` (`numOrNull`), не 0. Строки «СРЕДНИЕ ПОКАЗАТЕЛИ» и заголовки блоков пропускаются (в C нет даты).

**Итог T — формула E−F−H−J.** У группы, которая ещё учится, она показывает «сколько осталось сейчас», а не выход на линию. Поэтому итог и конверсия по-прежнему берутся только у законченных групп (D ≤ сегодня).

## Классификация строк

1. Нет валидной даты в `startDate` → строка игнорируется полностью.
2. `comment` содержит «не собралась», «не набралась» или «не состоялась» (регистр не важен, `groupStatusFromComment`) → счётчик `notGathered`, **не** в valid; с v8 строка всё равно уходит в `groups[]` с `notGathered: true` (только для показа).
3. Иначе → `validGroups` (участвует в списке стартов). Если `comment` содержит «распалась» или «расформирована» — группа **входит** в valid с меткой `fellApart: true` и увеличивается счётчик `fellApart`.
4. Законченная (`completed`): `fellApart` **или** `lineDate` (колонка D) ≤ сегодня (дата, таймзона `Asia/Oral`). Иначе — в обучении.

Порядок проверки: сначала «не собралась» (исключение), затем флаг «распалась» внутри valid, затем сверка D с сегодня.

Смысл: «не собралась» — группа не состоялась; «распалась» — старт был, поток уже закрыт (считается законченной сразу); действующая — D ещё в будущем, в KPI только как старт группы.

## Что входит в какие метрики

| Набор | Кто | Куда |
|-------|-----|------|
| Старт групп | все valid | `totals.groups`, `byTrainer.groups`, `byMonth.groups` |
| Outcome | только `completed` | day1, воронка, отсев, final, conv, yield, TQI, `fellApartShare` |
| Вне расчёта | «не собралась» | только `notGathered` |

## Нормализация имени тренера

`normalizeName`:

- trim, схлопывание пробелов
- удаление хвостов в скобках: `Иванов (стажёр)` → `Иванов`
- пустое → `Без имени`

## Проценты

`parsePercent`:

- пусто → `null`
- number → как доля/значение из Sheets (обычно 0..1)
- строка с `%` / `,` → число / 100

В JSON наружу проценты отдаются уже в шкале **0–100** с округлением `round1` (1 знак), кроме случаев `null`.

## Производные сущности

| Сущность | Как строится |
|----------|--------------|
| `byTrainer` | group-by тренер; `groups` = старты; outcome/TQI по законченным; `groupsCompleted` / `groupsInProgress` |
| `byMonth` | group-by `month`; старты vs outcome как totals |
| `groups` | map valid → GroupRow (`completed`, `lineDate`, `fellApart`) |
| `totals` / `funnel` | старт = все valid; суммы/rates/yield — законченные; `groupsCompleted` / `groupsInProgress` |
| `metrics` | TQI v3 веса (`line` + `skills`), пороги бейджей, `fellApartInValid`, мета `lineReview` |

## Лист-результат

- Имя: `Дашборд` (`DASHBOARD_SHEET_NAME`)
- Полностью пересобирается `buildDashboard()` (clear + charts recreate)
- Не является источником для веб-UI (UI читает только JSON)

## Правила изменения схемы

1. Добавили/переставили колонку в Sheet → если это новое поле, добавить шаблон в `HEADER_PATTERNS` и ключ в `COL`; переименовали заголовок обязательной колонки — проверить шаблон; обновить этот файл, при отдаче в API — ApiContract.
2. Переставили колонки → для скрипта не breaking (поиск по заголовкам). Breaking — только переименование заголовка обязательной колонки так, что шаблон перестал его узнавать: /exec вернёт ошибку со списком ненайденных колонок.
3. Подняли лимит строк >500 → изменить `DATA_END_ROW` и отметить здесь.
4. Не использовать «магические» номера колонок в frontend.
