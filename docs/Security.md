# Безопасность и данные

## Что считается чувствительным

| Данные | Где | Риск |
|--------|-----|------|
| Агрегаты обучения, имена тренеров, метки групп, средняя оценка после линии | JSON `/exec`, UI | Операционная информация |
| Сырые строки Sheet (возможны ПДн) | Google Sheets: обучение + журнал «Выход на линию — ОС» | Выше; **не отдавать** во внешний API |
| OAuth clasp (`.clasprc.json`) | Домашняя директория машины | Доступ к Apps Script аккаунта |
| Script ID / Deployment ID | Репо / docs | Сами по себе слабый секрет; URL `/exec` сильнее |

## Текущая модель доступа API

- Web App: выполняется от имени деплоера, доступ **Anyone (anonymous)**.
- Защита фактически = секретность URL + отсутствие ПДн в ответе.
- UI на Netlify публичный (или по политике Netlify), но без URL API бесполезен только частично (URL зашит в клиенте!).

> Важно: URL `/exec` **уже присутствует** в `index.html`. Считать API доступным всем, кто откроет исходники сайта.

## Обязательные правила

1. Не добавлять в JSON ФИО учеников, телефоны, email, сырые комментарии с ПДн, прогноз по сотруднику из журнала ОС.
2. Не коммитить `.clasprc.json`, `.env`, ключи сервис-аккаунтов.
3. Не вставлять пароли в query string как «защиту».
4. Перед расширением полей API — проверить Security + ApiContract.
5. При компрометации URL — новый deployment + смена URL в UI + invalidate старый (disable deployment).
6. Вторая книга (журнал ОС) читается от имени деплоера: достаточно «Читатель». Владеть файлом не нужно. Не копировать журнал «к себе» — будет второй источник.

Аккаунт, под которым задеплоен web app, должен иметь доступ к журналу ОС. Посетители дашборда этот файл не открывают.

## Минимальные права clasp (ориентир)

При логине достаточно узких scope под Apps Script projects/deployments + Drive files **created by this app**. Не выдавать «просмотр всех файлов Диска» без нужды.

## Если понадобится усилить защиту (будущее)

Варианты (только через ADR):

- Ограничить доступ Web App аккаунтам Google организации
- Прокси с auth (Netlify / Cloudflare Access) перед API
- Сервис-аккаунт + backend (уже другой класс системы)

## Инцидент: подозрение на утечку

1. Manage deployments → выключить/удалить скомпрометированный deployment.
2. Создать новый (или обновить с ротацией URL, если Google позволяет только новым).
3. Обновить `DEFAULT_APPS_SCRIPT_URL`, задеплоить UI.
4. Записать факт в Decisions / заметку инцидента.
5. Оценить, какие агрегаты могли увидеть посторонние.
