# Конвенции

## Язык

- UI, комментарии к бизнес-логике, docs — **русский**.
- Ключи JSON и технические идентификаторы — **английский camelCase** (`byTrainer`, `conv1to5`).
- Коммиты: коротко, по сути; можно по-русски или по-английски, но единообразно в серии.

## Frontend (`index.html`)

- Пока один файл — держать секции комментариями (`// ============`).
- Не тащить React/Vue без ADR и пункта Roadmap.
- Chart.js: всегда `destroyChart` перед пересозданием.
- Не считать бизнес-метрики иначе, чем контракт; presentation-only агрегаты из `groups[]` — ок, если согласованы с DataModel.
- Цвета/токены и иерархия текста — через CSS variables в `:root` (`--fs-hero` … `--fs-overline`).
- Всегда явно писать область данных: «весь период» или «месяц …»; стрелки MoM подписывать отдельно от крупных цифр.

## Apps Script (`apps-script/Код.js`)

- Стиль близкий к существующему: `var` + функции (V8, но без внезапного ESM).
- Конфиг только в блоке «НАСТРОЙКИ» вверху файла.
- Новые helper-ы — рядом с utils, с понятным именем.
- Не логировать содержимое строк Sheet в публичные места.

## Документация

- Индекс всегда актуален: [Index.md](Index.md).
- Breaking change JSON → ApiContract + совместный релиз.
- Архитектурный выбор → ADR в Decisions.md.
- Идея ≠ задача: Ideas → Roadmap.

## Git

- Ветка работы по умолчанию: `main` (пока без git-flow).
- Не коммитить: `.clasprc.json`, `.env*`, бэкапы `*.local.bak`, `node_modules`.
- `apps-script/.clasp.json` (scriptId) — **можно** коммитить.
- Не делать `push --force` в `main`.
- Коммиты и пуш — только по явной просьбе владельца (рабочее правило Cursor).

## Именование метрик

| Имя | Смысл |
|-----|-------|
| `conv1to5` | Конверсия с 1-го дня к выходу на линию |
| `conv2` / `conv3` | Конверсии с 2/3 дня |
| `leftSelf` | Ушли сами |
| `refused` | Отказали мы |
| `transferred` | Перенесли в другую группу |
| `finalCount` | Итоговый выход на линию (только законченные группы) |
| `completed` | Группа закончилась: D ≤ сегодня или «распалась» |
| `groupsInProgress` | Valid-группы, у которых дата линии ещё в будущем |

Новую метрику — новое имя поля; не перегружать старое другим смыслом.
